- (decision) Scope tuned to CLAIMABLE delays only (SWR Delay Repay 15+ min, banded); sub-15 lateness is noise and out of scope.
- (decision) Claim unit = per journey/per ticket, keyed to the intended train's scheduled DEPARTURE time; NOT the current worst-train-per-day collapse.
- (decision) Ticket types: single tickets now (~2 office days/week); season tickets likely later — data model must not preclude them.
- (decision) Filing is manual on the SWR website (only channel). MVP returns correct claimable-journey data for Simon to file by hand.
- (decision) Roadmap: MVP correct data on disk -> email digest -> Playwright/Selenium auto-fill SWR form -> ticket upload -> photo/OCR of ticket -> auto-claim; endgame AWS Lambda + API triggered when Simon photographs a ticket.
- (change) Current >1min threshold, both-legs-late drop, and worst-per-day pick are all WRONG for the Delay Repay goal and will be redefined.
- (change) MAJOR REFRAME: not journey-matching. Per-day optimisation over ALL route services to maximise claimable payout; 'which train I caught' is irrelevant.
- (decision) Feasibility constraint: chosen inbound (WAT->GOD) must depart AFTER the chosen outbound (GOD->WAT) arrives at WAT. Can't return before you've gone out.
- (decision) Selection within a leg: maximise SWR payout band; tie-break on EARLIEST train (e.g. two 16-min trains -> earliest; but 16-min@07:00 vs 39-min@08:00 -> take 08:00 as higher band).
- (decision) Prefer TWO claims/day (one out + one back) over one; earlier outbound is favoured partly to leave room for a claimable return later in the day.
- (decision) Q1 RESOLVED: objective is MAXIMISE TOTAL PAYOUT across the day (sum of both legs' bands). Not max number of claims. Earliest-outbound remains the tie-break.
- (override) Q3 CORRECTION (reverses earlier single-ticket assumption): Simon buys OPEN DAY RETURNs — valid on any train both ways that day. So 'any train I could have travelled on' is fully valid; NO ticket-evidence constraint. Season ticket possible later.
- (decision) Q2 RESOLVED: cancellations are a FALLBACK candidate only — actual late trains always take precedence. Cancellation delay = actual arrival of next catchable train MINUS scheduled arrival of the cancelled train.
- (decision) Q4 CONFIRMED: bands 15-29=25%,30-59=50%,60-119=100% single,120+=100% return; feasibility uses outbound ACTUAL arrival; delay measured at destination arrival.
