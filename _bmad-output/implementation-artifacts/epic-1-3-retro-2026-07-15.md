## What went well

1. **The hexagonal seam paid its rent immediately.** When the "missing 10th inbound" bug surfaced, the fix was a config-flag flip + a real fixture — *zero* architectural surgery. AD-6 pre-provisioned exactly this path; the pure optimiser already contained the cancellation logic behind a gate.
2. **Offline-first TDD with real-grounded fixtures.** 160 tests run with no network or secrets, yet `@recorded` fixtures anchor the logic to genuine HSP JSON. This is what made diagnosing the cancellation bug fast and safe — the whole pipeline could be re-run against cache/fixtures deterministically.
3. **The AD-5 fetch-failure contract.** "Not analysed" is kept strictly distinct from "no claim", so a failed fetch can never silently cost money — a correctness-first decision (NFR1) that held up.
4. **Determinism + idempotent cache (AD-10 / NFR4).** Re-running a week reproduces byte-identical output and doesn't re-hit the API — which is exactly why regenerating `claims.csv` from cache after the fix was trivial.
5. **Pre-provisioned open questions.** OQ1 (gate) and OQ2 (per-day cap in the objective signature) were designed as cheap-to-resolve later. Resolving OQ1 cost a fixture + a default flip, not a redesign.

## What was harder — lessons

1. **Real input formats diverge from the documented shape.** The exported multi-section portal credentials file broke the naive INI parser (`DuplicateOptionError`) and later caused a 401 (wrong section's credentials). *Lesson:* validate against a real sample of every external file/format early, not just the spec's idealized shape.
2. **The runtime environment is part of the contract.** AVG TLS interception, PowerShell `$env:` syntax, and a Unicode arrow crashing `--help` on the Windows console all consumed real effort. NFR3 rightly flagged TLS, but console encoding and shell ergonomics weren't captured. *Lesson:* treat "runs cleanly on the actual target shell/OS" as an explicit acceptance criterion.
3. **A gated-off correctness path is invisible until it bites.** Shipping FR12 OFF (synthetic tests only) was correct governance, but it meant a genuinely claimable event — the 10 Jul cancellation — was silently dropped until a manual cross-check caught it. *Lesson:* a disabled correctness path needs either a visible "this is off" signal in the output/summary, or a fast enable-on-real-data trigger.
4. **The composition root must own human ergonomics, too.** The first working CLI was too fiddly for daily use; it took a follow-up to add the one-liner MVP (`python -m trainline`) + QUICKSTART + progress logging. *Lesson:* "wire it end-to-end" should include the actual invocation a human will type, not just correct orchestration.
5. **Payout-equivalent ≠ what the user remembers.** The equal-band tie-break surfaces the *earliest* qualifying train, which is payout-correct but can mismatch the specific (worse-delayed) train a user recalls — friction during manual verification.

## Technical debt / open items carried forward

- **OQ2 (payout model)** — still open: band % base (single vs return), and whether SWR caps stacked outbound+inbound claims per day. Affects real filing amounts. The optimiser objective already accepts a per-day cap, so resolution is a value, not a rewrite.
- **OQ3 (form mapping)** — validated 2026-07-15. Two concrete follow-ups for the automation phase: map `reason` (raw HSP `late_canc_reason` code) → the SWR "Delay reason" category (Delayed en route / Train cancelled / …), and add a CRS→station-name map (WAT→London Waterloo, GOD→Godalming).
- **`reason` column** currently emits a raw numeric HSP code — not human-friendly.
- **Live credential-probe suite** is broad (probes many Open Rail Data products). Useful, but heavier than the MVP strictly needs; keep it opt-in/gated.

## Key takeaways

1. The frozen hexagonal architecture and the pre-provisioned gates (AD-6/OQ1, AD-10 cap) turned a "bug" into a one-flag change — architectural discipline compounded.
2. Offline-first + real-grounded fixtures made both delivery and later debugging cheap and safe.
3. The biggest real-world friction was *outside* the domain logic — credentials, TLS, shell, and the human-facing command — which is where the next round of hardening should focus.
